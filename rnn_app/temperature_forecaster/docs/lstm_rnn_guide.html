1. RNN Fundamentals

A Recurrent Neural Network (RNN) is a class of neural networks designed to process sequential data — data where order matters. Unlike feedforward networks that treat each input independently, RNNs maintain a hidden state that carries information from previous timesteps, creating a form of memory.

Why Sequential Data Needs Special Treatment

Consider predicting tomorrow's temperature. A standard neural network would look at today's temperature in isolation. But temperature follows patterns — it was warm yesterday, cooling today, so it might be cooler tomorrow. An RNN captures these temporal dependencies by maintaining state across timesteps.

The RNN Cell

At each timestep t, an RNN cell takes two inputs:

  • x_t — the current input (e.g., today's temperature)
  • h_{t-1} — the hidden state from the previous timestep (memory)

And produces:

  • h_t — the new hidden state (updated memory)
h_t = tanh(W_hh · h_{t-1} + W_xh · x_t + b_h)
x_1 x_2 x_3 x_4 | | | | ┌────▼────┐ ┌────▼────┐ ┌────▼────┐ ┌────▼────┐ │ RNN │──│ RNN │──│ RNN │──│ RNN │ │ Cell │ │ Cell │ │ Cell │ │ Cell │ └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘ | | | | h_1 h_2 h_3 h_4 | ┌────▼────┐ │ Output │ │ Layer │ └────┬────┘ | y_hat

The same weight matrices W_hh and W_xh are shared across all timesteps. This parameter sharing is what makes RNNs efficient for sequences of any length — the model size does not grow with sequence length.

2. The Vanishing Gradient Problem

While RNNs are theoretically capable of learning long-range dependencies, in practice they struggle. During backpropagation through time (BPTT), gradients must flow through many timesteps. At each step, the gradient is multiplied by the weight matrix and passed through the tanh derivative.

The Core Problem

When the tanh derivative (which is always ≤ 1) and weight values are repeatedly multiplied across many timesteps, the gradient either:

  • Vanishes (approaches 0) — the network cannot learn from distant past inputs
  • Explodes (grows extremely large) — training becomes unstable

For temperature forecasting with 120 hourly observations, a vanilla RNN would struggle to learn patterns from 5 days ago because the gradient signal would effectively disappear after passing through ~120 multiplication steps.

This is precisely why LSTMs were invented.

3. LSTM Architecture

The Long Short-Term Memory (LSTM) network, introduced by Hochreiter & Schmidhuber (1997), solves the vanishing gradient problem with a carefully designed gating mechanism. Instead of a single hidden state, an LSTM cell maintains two states:

  • Cell state c_t — the long-term memory highway
  • Hidden state h_t — the working memory / output

The Four Components of an LSTM Cell

1. Forget Gate

Decides what information to discard from the cell state.

f_t = σ(W_f · [h_{t-1}, x_t] + b_f)

The sigmoid function σ outputs values between 0 and 1. A value of 0 means "completely forget this," and 1 means "completely keep this." For temperature forecasting, the forget gate might learn to discard information from unusually anomalous readings while retaining the general trend.

2. Input Gate

Decides what new information to store in the cell state.

i_t = σ(W_i · [h_{t-1}, x_t] + b_i)
&ctilde;_t = tanh(W_c · [h_{t-1}, x_t] + b_c)

The input gate has two parts: a sigmoid layer decides which values to update, and a tanh layer creates a vector of candidate new values. Together, they determine what new information enters the cell state.

3. Cell State Update

Combines the forget gate and input gate to update the long-term memory.

c_t = f_t * c_{t-1} + i_t * &ctilde;_t

This is the key innovation: the cell state is updated through addition, not multiplication. Gradients can flow through the addition operation without vanishing, enabling the network to remember information across many timesteps.

4. Output Gate

Decides what part of the cell state to output as the hidden state.

o_t = σ(W_o · [h_{t-1}, x_t] + b_o)
h_t = o_t * tanh(c_t)

The output gate filters the cell state to produce the hidden state, which serves as both the output at this timestep and the input to the next LSTM cell.

Cell State Highway (c_{t-1} ──────────────► c_t) │ ▲ │ ┌─────────┐ │ ├────►│ Forget │──── × ───┤ │ │ Gate │ │ │ └─────────┘ │ │ ┌─────┤ │ ┌─────────┐ │ │ ├────►│ Input │── × ── + ─ │ │ Gate │ │ │ └─────────┘ │ │ ┌─────────┐ │ ├────►│Candidate │────┘ │ │ (tanh) │ │ └─────────┘ │ ┌─────────┐ └───────────────────────►│ Output │──► h_t │ Gate │ [h_{t-1}, x_t] └─────────┘

Why LSTMs Work for Long Sequences

The cell state acts as a highway for gradient flow. During backpropagation, the gradient passes through the cell state update equation:

∂c_t / ∂c_{t-1} = f_t (+ other terms)

Since f_t is controlled by a learned gate (not a fixed weight matrix), the network can learn to keep the forget gate close to 1 for important long-term information, allowing gradients to flow unimpeded across hundreds of timesteps.

4. Time-Series Forecasting with LSTMs

Time-series forecasting is the task of predicting future values based on past observations. Temperature is a classic example — it follows daily cycles (warm during day, cool at night), seasonal patterns (warm in summer, cold in winter), and weather-driven trends.

Classification vs. Regression

The LSTM processes the sequence of past temperatures and its final hidden state h_T encodes the temporal patterns. A linear layer then projects this encoding to a single predicted value.

5. The Sliding Window Approach

To train an LSTM for forecasting, we need to create input-output pairs from the raw time series. The sliding window (or rolling window) approach does this by moving a fixed-size window across the data:

Time Series: [t1, t2, t3, t4, t5, t6, t7, t8, t9, ...] Window size = 5: Window 1: [t1, t2, t3, t4, t5] → target: t6 Window 2: [t2, t3, t4, t5, t6] → target: t7 Window 3: [t3, t4, t5, t6, t7] → target: t8 Window 4: [t4, t5, t6, t7, t8] → target: t9 ...

Each window becomes one training sample. The input X is the window of past values, and the target y is the next value immediately following the window.

Choosing Window Size

In our implementation, we use a window of 120 hourly observations (5 days). This choice captures:

  • Daily cycles — the 24-hour temperature oscillation (day/night)
  • Multi-day trends — warming or cooling trends over several days
  • Weather patterns — frontal systems that typically last 2-5 days

A window that is too short (e.g., 6 hours) would miss daily cycles. A window that is too long (e.g., 30 days) would add computational cost without proportional benefit, as very old data has diminishing predictive value for the next hour.

6. Min-Max Normalization

Neural networks learn most efficiently when input values are small and in a consistent range. Raw temperature values in the Jena dataset range from approximately -23°C to +37°C. Min-Max scaling transforms these to the range [0, 1]:

x_normalized = (x - x_min) / (x_max - x_min)

For the inverse transformation (converting predictions back to °C):

x_original = x_normalized × (x_max - x_min) + x_min
Why Normalize?
  • Gradient stability — Large input values produce large gradients, which can cause unstable training. Normalized values keep gradients in a manageable range.
  • Faster convergence — When inputs are on a similar scale, the loss surface is more uniform, and gradient descent converges faster.
  • Numerical precision — Float32 arithmetic is more precise near 0 than at large magnitudes.

Min-Max vs. Standard Scaling

Method Formula Range Best For
Min-Max (x - min) / (max - min) [0, 1] Bounded data, preserves distribution shape
Standard (Z-score) (x - mean) / std Unbounded Gaussian-distributed data, outlier-resistant

We chose Min-Max scaling because temperature has natural physical bounds and we want the output to be bounded, matching common neural network activation ranges.

7. Training the Model

Training optimizes the model's weights to minimize prediction error. Our training loop follows these steps for each epoch:

1Forward pass — Feed a batch of input sequences through the LSTM to get predictions.

2Loss computation — Calculate Mean Squared Error between predictions and actual values.

MSE = (1/N) ∑ (y_i - ŷ_i)²

3Backpropagation through time (BPTT) — Compute gradients of the loss with respect to all weights by unrolling the LSTM across timesteps.

4Gradient clipping — Cap gradient norms at 1.0 to prevent exploding gradients.

if ||g|| > 1.0: g ← g × (1.0 / ||g||)

5Weight update — Apply the Adam optimizer to update weights.

W ← W - α · ∂L/∂W

Training Strategies

Early Stopping

We monitor validation loss after each epoch. If it does not improve for 10 consecutive epochs, training stops early to prevent overfitting. The best model checkpoint (lowest validation loss) is restored.

Learning Rate Scheduling

We use ReduceLROnPlateau — if validation loss plateaus for 5 epochs, the learning rate is halved. This allows fine-grained optimization as the model approaches a minimum.

Chronological Data Split

Time-series data must be split chronologically, not randomly. Random splitting would leak future information into the training set (data leakage), producing misleadingly good results. We use the earliest 80% for training and the most recent 20% for testing.

8. Evaluation: RMSE

Root Mean Squared Error (RMSE) is the standard evaluation metric for regression tasks. It measures the average magnitude of prediction errors:

RMSE = √( (1/N) ∑ (y_i - ŷ_i)² )
Why RMSE?
  • Same units — RMSE is in °C, making it directly interpretable. An RMSE of 2.0 means "predictions are off by about 2°C on average."
  • Penalizes large errors — Squaring amplifies large deviations more than small ones, which is desirable (a 10°C error is much worse than ten 1°C errors).
  • Differentiable — Compatible with gradient-based optimization (MSE is the square of RMSE).

Interpreting RMSE

RMSE (°C) Interpretation
< 1.0 Excellent — predictions are very close to actual values
1.0 - 2.0 Good — typical for hourly temperature prediction
2.0 - 4.0 Moderate — room for improvement
> 4.0 Poor — model may need more capacity or data

Why Subsample to Hourly?

The raw dataset at 10-minute intervals contains ~420,000 data points. Using all of them with a window of 720 timesteps (5 days at 10-min resolution) would create an enormous number of training sequences. By subsampling every 6th row, we get hourly data (~70,000 points) with a window of 120 timesteps (still 5 days). This dramatically reduces computation while preserving the important temperature patterns.

10. Our Implementation

Model Architecture

Input: (batch, 120, 1) — 120 hours of normalized temperature │ ┌──────▼──────┐ │ LSTM │ hidden_size=64 │ Layer 1 │ processes all 120 timesteps └──────┬──────┘ │ ┌──────▼──────┐ │ Dropout │ p=0.2 └──────┬──────┘ │ ┌──────▼──────┐ │ LSTM │ hidden_size=64 │ Layer 2 │ returns final hidden state h_T └──────┬──────┘ │ ┌──────▼──────┐ │ Dropout │ p=0.2 └──────┬──────┘ │ ┌──────▼──────┐ │ Linear │ 64 → 1 └──────┬──────┘ │ Output: (batch, 1) — predicted temperature (normalized)

PyTorch Implementation

class TemperatureLSTM(nn.Module):
    def __init__(self, input_size=1, hidden_units=64,
                 num_layers=2, dropout_rate=0.2):
        super().__init__()
        self.lstm = nn.LSTM(
            input_size=input_size,
            hidden_size=hidden_units,
            num_layers=num_layers,
            batch_first=True,
            dropout=dropout_rate if num_layers > 1 else 0.0
        )
        self.dropout = nn.Dropout(dropout_rate)
        self.fc = nn.Linear(hidden_units, 1)

    def forward(self, x):
        # x: (batch, seq_len, 1) — normalized temperatures
        out, (h, c) = self.lstm(x)
        # h[-1]: final hidden state from last LSTM layer
        final_hidden = self.dropout(h[-1])
        return self.fc(final_hidden)  # (batch, 1)

Data Pipeline

# 1. Load CSV
df = pd.read_csv('jena_climate_2009_2016.csv')

# 2. Subsample to hourly (every 6th row)
df = df.iloc[::6].reset_index(drop=True)

# 3. Extract temperature column
temperature = df['T (degC)'].values

# 4. Min-Max normalize to [0, 1]
scaler = MinMaxScaler()
normalized = scaler.fit_transform(temperature.reshape(-1, 1))

# 5. Create sliding window sequences
X, y = [], []
for i in range(120, len(normalized)):
    X.append(normalized[i-120:i])  # 120 past hours
    y.append(normalized[i])         # next hour

# 6. Chronological split (80/20)
split = int(len(X) * 0.8)
X_train, X_test = X[:split], X[split:]
y_train, y_test = y[:split], y[split:]

12. Observations and Results

Key Observations
  1. Daily patterns are learned quickly — The model captures the 24-hour temperature cycle within the first few epochs, as this is the strongest signal in the data.
  2. Seasonal trends require more data — The model sees seasonal variation across the 5+ years of data. The chronological test split means the test set contains weather patterns not seen in training (the most recent years).
  3. Extreme temperatures are harder — The model tends to under-predict temperature spikes and over-predict cold snaps, as these events are less frequent in the training data.
  4. Subsampling to hourly is effective — 10-minute resolution adds noise without meaningful additional information for next-hour prediction.
  5. Two LSTM layers outperform one — The second layer helps capture hierarchical patterns (intra-day variation on layer 1, multi-day trends on layer 2).

Potential Improvements

  • Multivariate input — Include pressure, humidity, and wind speed as additional features. These variables influence temperature and could improve predictions.
  • Attention mechanisms — Allow the model to attend to specific past timesteps rather than relying on a compressed hidden state.
  • Longer prediction horizons — Predict 24 or 48 hours ahead instead of just the next hour, using a sequence-to-sequence architecture.
  • Ensemble methods — Train multiple models with different hyperparameters and average their predictions for more robust forecasting.
  • Transformer-based models — Modern architectures like the Temporal Fusion Transformer can outperform LSTMs on complex time-series tasks.
