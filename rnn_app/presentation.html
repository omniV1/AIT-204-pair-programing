The Jena Climate dataset comes from the Max Planck Institute — 14 different weather measurements every 10 minutes for 8 years. We only used the temperature column.

Why LSTM over vanilla RNN?

Our input window is 120 time steps long. A basic RNN just can't hold onto information across that many steps — the gradients vanish. LSTMs were built to fix that.

Data Preprocessing: Loading & Normalizing

Raw temperatures range from about −8 to 39. Neural networks learn faster when inputs are scaled to [0, 1], so we normalize right after loading.

Loading the CSV

df = pd.read_csv(csv_path) # (420551, 15) step = 6 # Downsample to hourly df = df.iloc[::step].reset_index(drop=True) # (70092, 15) temperature = df['T (degC)'].values
Why hourly? Temperature doesn't change meaningfully in 10 minutes. Hourly resolution keeps every useful pattern and trains much faster.

Min-Max Scaling

xnorm = (x − xmin) / (xmax − xmin)
scaler = MinMaxScaler(feature_range=(0, 1)) normalized = scaler.fit_transform( data.reshape(-1, 1) ) # Scaler remembers min/max for # converting predictions back to °C
Why Min-Max over StandardScaler? Temperature has hard physical bounds — it's not unbounded like, say, stock returns. Min-Max maps directly to [0, 1] which lines up with the sigmoid activations inside the LSTM.
Sequence Creation & Train/Test Split

LSTMs don't look at individual numbers — they need sequences. We slide a 120-hour window across the data, where each window becomes one input and the next value is the target.

Sliding Window (5 days = 120 hours)

X[0] = [t1, ..., t120] → y[0] = t121
X[1] = [t2, ..., t121] → y[1] = t122
X[2] = [t3, ..., t122] → y[2] = t123
X, y = [], [] for i in range(seq_length, len(data)): X.append(data[i - seq_length : i]) y.append(data[i]) X = np.array(X).reshape(-1, 120, 1)

Chronological Train/Test Split

No shuffling. With time-series data you can't randomly split — that would leak future information into training. First 80% trains, last 20% tests.
split = int(len(X) * 0.8) X_train = X[:split] # 2009-2014ish X_test = X[split:] # 2015-2016 # Also hold out 10% of training for validation

Why these choices?

LSTM over vanilla RNN

120 time steps is a long sequence. Plain RNNs lose gradient signal well before reaching that far back. LSTM gates fix this.

Two layers

Layer 1 picks up hour-to-hour fluctuations. Layer 2 can then look at those patterns and find bigger things like day/night cycles.

No embedding

Temperature is already a continuous number. After normalizing it just goes straight in — no need to convert tokens to vectors like you would with text.

Single output, MSE loss

This is regression. One number comes out, and we penalize squared error.

LSTM Gates: How It Works

Each LSTM cell maintains two vectors: a hidden state (h) and a cell state (c). Three gates control what to forget, what to add, and what to output at each step.

Forget Gate
ft = σ(Wf · [ht-1, xt] + bf)
Decides how much of the old cell state to keep. 0 = throw it away, 1 = keep all of it.
Input Gate
it = σ(Wi · [ht-1, xt] + bi)
Decides which new information is worth storing. Scales the candidate values below.
Candidate
ĉt = tanh(Wc · [ht-1, xt] + bc)
Proposes new values to write into cell state. Input gate scales these before they're added.
Cell Update
ct = ft * ct-1 + it * ĉt
Old memory scaled by forget gate, plus new info scaled by input gate.
Output Gate
ot = σ(Wo · [ht-1, xt] + bo)
Controls which parts of the cell state get exposed as this time step's output.
Hidden State
ht = ot * tanh(ct)
The cell's output. Passed to both the next time step and (at step 120) to the linear layer.
In practice, the forget gate learns to ignore random temperature spikes, while the cell state tracks the broader trend. That selective memory over 120 steps is exactly what vanilla RNNs can't do.

Optimizer Setup

criterion = nn.MSELoss() optimizer = torch.optim.Adam( model.parameters(), lr=0.001 ) scheduler = ReduceLROnPlateau( optimizer, factor=0.5, patience=5, min_lr=1e-6 )
~45K parameters total. We tried larger networks but they didn't help — started overfitting instead. For one input feature, this size is plenty.
Model Training

We wrote the training loop manually in PyTorch so we could control gradient clipping, checkpointing, and early stopping ourselves.

for epoch in range(max_epochs): model.train() for X_b, y_b in train_loader: preds = model(X_b) loss = criterion(preds, y_b) optimizer.zero_grad() loss.backward() clip_grad_norm_(model.parameters(), 1.0) optimizer.step() model.eval() with torch.no_grad(): val_loss = run_validation() scheduler.step(val_loss) maybe_save_checkpoint(val_loss) maybe_early_stop(val_loss)
Loss = MSE = (1/N) ∑ (yi − ŷi)²

Keeping It Stable

Checkpointing

We save the weights whenever validation loss drops to a new low, then load the best checkpoint at the end.

Early stopping

If validation doesn't improve for 10 epochs in a row, training stops.

LR decay

Learning rate gets halved automatically when loss stalls for 5 epochs.

Gradient clipping

Backprop through 120 steps can blow up gradients. Clipping at norm 1.0 prevents that.

Revisions: Changes We Made

The first version was a plain RNN and it didn't work well. These are the iterations that actually moved the needle.

RNN → LSTM

This was the single biggest improvement. The vanilla RNN just couldn't learn from 120 steps back — gradients vanished. Switching to LSTM cut test error by about 40%.

Added a second layer

One LSTM layer was decent but plateaued early. Adding a second one let the model build higher-level features on top of the first layer's raw patterns.

Dropout + early stopping

Without these, the model memorized training noise around epoch 30. Dropout (0.2) and early stopping (patience 10) brought it back in line.

Learning rate decay

With a fixed learning rate, training stalled around epoch 20. ReduceLROnPlateau halves it when progress stops, which helped a lot in later epochs.

Window size tuning

We tried 24 hours (too short, missed multi-day patterns), 720 hours (too slow, no improvement), and settled on 120 hours (5 days).

Gradient clipping

Loss kept spiking randomly early in training. Turned out gradients were exploding through the long sequences. Clipping at 1.0 stabilized everything.

The RNN-to-LSTM switch was worth more than every other change combined. Without gating, the model couldn't use a 5-day window at all. Everything else was incremental.

Takeaways
LSTMs vs. RNNs

Watching the vanilla RNN fail on this exact dataset and then seeing the LSTM handle it made the theory click. With 120 input steps, the difference is obvious.

Data prep matters more than architecture

Normalization, subsampling, and the chronological split all mattered more than any model change. A bigger network with sloppy data prep gives you nothing.

You need all the regularization

Dropout alone didn't cut it. Early stopping alone didn't either. All three (dropout, early stopping, LR scheduling) working together is what made the difference.

Plotting > staring at numbers

The loss plot immediately showed when overfitting started. The prediction plot showed exactly where the model struggled. We wouldn't have caught those from RMSE alone.
